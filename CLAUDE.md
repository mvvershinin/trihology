## Overview

Десктопное приложение для трихоскопического анализа волос с USB-микроскопа.
Замена коммерческого ПО стоимостью 50-150к рублей.

- **Язык**: Python 3.11+
- **GUI**: tkinter (ttk)
- **CV**: OpenCV + NumPy
- **БД**: SQLite3 (stdlib)
- **Графики**: matplotlib
- **Отчёты**: fpdf2
- **Сборка**: PyInstaller → AppImage (Linux)
- **Платформа**: Linux (Windows — в дорожной карте)
- **Интерфейс**: полностью на русском
- **Конфигурация**: `pyproject.toml` — единый источник (ruff, mypy, pytest, import-linter)

**Методология**: `docs/METHODOLOGY.md`
**Архитектура**: `docs/ARCHITECTURE.md`
**Задачи**: `docs/todo/BACKLOG.md` (единый трекер; датированные файлы — история)

## Десктоп под Windows: правила, купленные чужими шишками

Перенесено 06.09.2026 из соседнего проекта того же владельца (десктоп на Python,
Windows + Linux, портативная поставка). Разбор каждого пункта с замерами —
[`docs/WINDOWS_LESSONS.md`](docs/WINDOWS_LESSONS.md). Здесь — только то, что
обязано быть в голове всегда.

| Правило | Что за ним стоит |
|---|---|
| **«Собралось» ≠ «запускается у пользователя»** | Проверка только на машине без Python, с `PATH` до `system32` и без VC++ Redistributable. Три разных класса отказа |
| **Проверка идёт тем путём, которым пойдёт человек** | Там отдали сборку, ни разу не нажав главную кнопку: гоняли из консоли, где этот путь не задействован. Кнопка не работала вовсе. Цена — ночь времени владельца. Прогон из консоли, снимок экрана и зелёные тесты — три разные вещи, и ни одна не заменяет запуск так, как запустит человек |
| **Молчание — самостоятельный дефект** | Трижды за сутки исправное поведение приняли за поломку: программа знала ответ и не сказала. Отказ, не доехавший до человека, равен поломке и стоит дороже — поломку чинят, молчание ищут |
| **Состояние, выбираемое один раз за процесс, откату не поддаётся** | Откат переменной не откатывает последствие, которое она вызвала. ⚠️ У нас это `matplotlib.use("TkAgg")` на уровне модуля в `gui/multizone_tab.py:27` и `gui/history_tab.py:37` — закрепляет бэкенд на весь процесс, включая тесты без интерфейса. **Проверить:** `pytest -q` и `env -u DISPLAY -u WAYLAND_DISPLAY pytest -q` обязаны дать одинаковый результат |
| **Тест в одиночку и тест в компании — разные тесты** | Там прогнали каждый из 3413 тестов отдельно: 18 не работали в одиночку, из них двое стерегли утечку секрета. За трое суток нашли 17 «вакуумных» сторожей — и ни разу не сделали самое дешёвое, одиночный запуск. Мутация ловит «сторож не падает на поломке», одиночный запуск — «сторож зеленеет от соседей». Это разные дефекты |
| **Одна копия программы на одни данные** | Данные лежат в `~/.phototrichogram` — **одни на все копии**. Две запущенные копии дадут гонку за `config.json` и устаревшие данные во второй. Замок держит система на дескрипторе, а не наличие файла, и **отказывает словами**, а не молча |
| **Без подписи кода репутация считается по хешу файла** | Значит платится заново на каждый релиз. Упаковщики не использовать, имя и структуру пакета между релизами не менять, в инструкции — отдельный раздел про первый запуск |

⚠️ **Что в этих правилах гипотеза, а не факт.** Пункты про `matplotlib.use` и
про две копии получены **чтением нашего кода**, без единого прогона. Проверить
и подтвердить — до того, как на них опираться.

✅ **Что у нас уже сделано правильнее, чем у них:** данные пользователя лежат
**вне** папки программы. У них наоборот, и это красный долг: обновление заменой
папки снесло бы базу и настройки. Не переносить папку данных внутрь поставки
ни под каким предлогом.

## Архитектурные правила

### Модульная структура (4 слоя)

```
GUI (gui/)
 ├──→ Reports (reports/)   PDF-отчёты, fpdf2 (код с v1.1)
 ├──→ Core (core/)         OpenCV/NumPy
 └──→ Data (data/)         SQLite3
Reports ──→ Core, Data (модели)

core/ и data/ независимы друг от друга; utils/ — нижний слой, доступен всем.
Контракт import-linter: gui → reports → (core | data) → utils.
Проверка: `lint-imports` (контракт в pyproject.toml).
```

### СТРОГО ЗАПРЕЩЕНО

| Запрет | Почему |
|--------|--------|
| cv2 вызовы в gui/ | Нарушение слоёв |
| tkinter в core/ | Core должен быть testable без GUI |
| sqlite3 в core/ | Core не знает о хранилище |
| Хардкод параметров анализа | Все пороги — через конфиг |
| cv2.imshow() | Показ через tkinter |
| print() вместо logging | Не отключается в релизе |
| f-string в SQL | SQL injection |
| Английский текст в UI | Интерфейс на русском. Исключение: клинические термины Terminal/Vellus/T/V — общепринятая трихологическая номенклатура |

### ОБЯЗАТЕЛЬНО

| Правило | Зачем |
|---------|-------|
| Все параметры анализа — настраиваемые | Разные микроскопы, разные пороги |
| dataclasses для моделей | Типизация, автокомплит |
| pathlib.Path для путей | Кроссплатформенность |
| logging вместо print | Уровни, отключение |
| Type hints везде | Автокомплит, mypy |
| Docstrings на русском | Понятность |
| pytest тесты | Качество кода |

## Конфигурация — ВСЕ настраиваемое

```python
@dataclass
class AnalysisConfig:
    # Калибровка
    um_per_px: float = 5.9
    fov_width_px: int = 640
    fov_height_px: int = 480

    # Пороги сегментации
    clahe_clip_limit: float = 2.0
    clahe_tile_size: int = 8
    median_blur_kernel: int = 5
    morph_kernel_size: int = 3
    morph_close_iterations: int = 1
    morph_open_iterations: int = 1

    # Пороги детекции (эмпирически подстроены, см. METHODOLOGY.md §7.1)
    min_hair_area: int = 150
    max_circularity: float = 0.6

    # Классификация
    vellus_threshold_um: float = 30.0
    intermediate_threshold_um: float = 40.0

    # Расчётные (автоматически)
    @property
    def vellus_threshold_px(self) -> float:
        return self.vellus_threshold_um / self.um_per_px

    @property
    def fov_area_mm2(self) -> float:
        w_mm = self.fov_width_px * self.um_per_px / 1000
        h_mm = self.fov_height_px * self.um_per_px / 1000
        return w_mm * h_mm
```

## Права USB

Для работы микроскопа без sudo нужны udev-правила:
```bash
sudo bash install-udev.sh
```
Скрипт ставит правило `/etc/udev/rules.d/99-phototrichogram.rules`
(`SUBSYSTEM=="video4linux", GROUP="video", MODE="0660"`) и подсказывает
добавить пользователя в группу `video` (`sudo usermod -aG video $USER` +
перевход в сессию), если он ещё не состоит в ней.

Временное решение — без установки правила, до перезагрузки:
```bash
sudo chmod a+rw /dev/video*
```
