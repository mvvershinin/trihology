# Сборка и поставка под Windows

**Обновлено:** 07.11.2026. Основной путь — нативный PyInstaller onedir на
Windows runner GitHub Actions. Ниже также сохранён резервный Linux→Windows
рецепт с другим устройством папки. Не смешивайте их команды запуска.
Текущий статус первого выпуска — в [плане](todo/2026-11-07_планы-и-github-релизы.md).

Развёртывание с пустой базой на целевом ПК: [инструкция агенту](WINDOWS_SETUP_AGENT.md).

## Готовая программа

Откройте [GitHub Releases](https://github.com/mvvershinin/trihology/releases/latest).
В опубликованном релизе скачайте **Phototrichogram-win64.zip** и, если хотите
проверить целостность, **SHA256SUMS**. Если релиз ещё не появился, ZIP нельзя
заменять исходным архивом «Source code»: он не содержит готовой программы.

1. Распакуйте ZIP **целиком**, затем запустите `phototrichogram.exe` внутри
   распакованной папки. Не запускайте прямо из окна архива.
2. Python и SQLite отдельно устанавливать не нужно. Права администратора
   для запуска не требуются. Целевая система — Windows 10/11 x86_64.
3. Неподписанная программа может вызвать SmartScreen. Убедитесь, что скачали
   ожидаемый выпуск из указанного репозитория. Для ожидаемого файла Windows
   может предложить «Подробнее» → «Выполнить в любом случае».
4. Подключите UVC-микроскоп, откройте «Захват», обновите список и подключитесь.
   Если камера не работает, попробуйте DirectShow/Media Foundation в настройках.

Проверка SHA-256 в PowerShell: `Get-FileHash .\Phototrichogram-win64.zip -Algorithm SHA256`.
Сравните значение со строкой этого файла в SHA256SUMS.

Данные: `%USERPROFILE%\.phototrichogram`. Они не лежат в папке программы.
Перед обновлением закройте программу и сделайте резервную копию базы через
«Файл». Распакуйте новый выпуск в отдельную папку. Старую папку программы
можно сохранить для отката; при изменении схемы БД откат требует также
подходящей резервной копии данных. Одновременно две версии не запускайте.

## Релизный процесс

- CI проверяет код на push/PR. Тег `vX.Y.Z` запускает проверки коммита и сборки
  Linux AppImage и Windows ZIP; публикация возможна только после обеих.
- Ручной запуск workflow — пробная сборка с артефактами Actions, без публикации.
- Версия берётся из тега и проверяется в программе; к файлам прилагаются
  `SHA256SUMS` и `build-info.json` с ревизией и сведениями о сборке.
- Для обычных jobs достаточно `contents: read`; job публикации использует
  `contents: write` штатного GITHUB_TOKEN. Пользовательский токен в код не нужен.
- Нативная основа: `pyinstaller build.spec --noconfirm` на Windows после
  установки зависимостей. Полный рецепт и закреплённые инструменты —
  в `.github/workflows/release.yml` и вызываемых им сборочных скриптах.
  Для выпуска используйте именно полный рецепт, а не отдельную команду PyInstaller.

**Проверки различаются:** автоматический smoke готового ZIP проверяет доступный
без камеры сценарий, ресурсы и зависимости на runner. Он не доказывает запуск
на чистой машине без Python/внешнего VC++ runtime и не подтверждает работу
реального USB-микроскопа. Эти проверки остаются ручной приёмкой; результат
указывается в релизе. Наличие файла в Releases само по себе приёмкой не является.

## Если релизная программа не запускается

Проверьте полную распаковку ZIP и журнал
`%USERPROFILE%\.phototrichogram\phototrichogram.log`. Если журнала нет, запишите
сообщение Windows и версию скачанного релиза: отказ мог произойти до старта
приложения. Не используйте команды `runtime\python.exe app\start.py` для
релизного PyInstaller ZIP — они относятся только к резервному пакету ниже.

## Резервный способ: Windows runtime собирается на Linux

Этот раздел описывает прежний пакет `Фототрихограмма.bat` + `runtime/` + `app/`.
Он сохранён как альтернатива нативной сборке; размеры ниже относятся к старой
поставке, а не являются обещанием размера нового релиза.

### Р1. Пользователь резервного пакета

**Ничего устанавливать не требуется.** Ни Python, ни библиотек, ни базы данных,
ни драйверов, ни прав администратора.

| | |
|---|---|
| Система | Windows 10 или 11, 64-разрядная |
| Место на диске | ~350 МБ распакованный пакет |
| Оборудование | USB-микроскоп (UVC-совместимый) — драйвер у Windows встроенный |

Порядок: распаковать ZIP целиком в любую папку → запустить
`Фототрихограмма.bat`. Из архива, не распаковывая, программа не работает.

Отдельного упоминания заслуживает **SQLite**: его не нужно устанавливать и
искать в системе. SQLite — не сервер и не служба, а библиотека, которую Python
носит с собой; в пакете это файлы `runtime/DLLs/_sqlite3.pyd` и
`runtime/Library/bin/sqlite3.dll`. База данных — один файл `.db` в папке
пользователя. Ни порта, ни пароля, ни установщика.

При первом запуске Windows может показать предупреждение SmartScreen: программа
не подписана. Сначала проверьте источник и контрольную сумму файла; для
ожидаемого пакета интерфейс Windows может предложить «Подробнее» →
«Выполнить в любом случае».

---

### Р2. Требования резервной сборки

Сборка идёт **на Linux**. Windows-машина не нужна.

| | |
|---|---|
| Система | Linux x86-64 |
| Софт | `python3` с `pip`, `git` |
| Права | обычный пользователь, **sudo не нужен** |
| Сеть | доступ к PyPI, conda-forge (`conda.anaconda.org`) и GitHub |
| Место | ~1.5 ГБ (рабочий каталог + результат) |
| Время | 5–15 минут на первую сборку, дальше быстрее (скачанное переиспользуется) |

Wine ставить **не нужно** и не следует: он тянет под три сотни пакетов, а
задачу не решает — компилировать всё равно нечего.

### Команда

```bash
cd /путь/к/trihology
python tools/build_windows_package.py --out dist/windows
```

Результат:

```
dist/windows/Phototrichogram/           каталог пакета (~350 МБ)
dist/windows/Phototrichogram-win64.zip  архив для раздачи (~122 МБ)
```

Повторная сборка переиспользует скачанное из `dist/windows/_build`. Чтобы
скачать всё заново — удалить этот каталог. Своё место для промежуточных файлов
задаётся ключом `--work`.

---

### Р3. Почему на Linux не PyInstaller

PyInstaller упаковывает интерпретатор **той системы, на которой запущен**.
Кросс-сборки он не умеет: `.exe` под Windows делается только на Windows. Это
ограничение самого инструмента, а не недоработка проекта.

Скрипт идёт другим путём: он не собирает, а **складывает вместе готовые
бинарники для Windows**. Ни одна строчка кода при сборке не компилируется —
всё скачивается уже собранным под Windows:

1. **Windows-Python** из conda-forge (`micromamba create --platform win-64`).
   Выбран потому, что в этой сборке уже есть tkinter, tcl/tk и SQLite —
   официальный «встраиваемый» Python с python.org идёт без tkinter, а значит,
   без интерфейса.
2. **Windows-колёса библиотек** с PyPI
   (`pip download --platform win_amd64 --only-binary=:all:`) — распаковываются
   в `site-packages` как обычные zip-архивы.
3. **Исходники приложения** и каталог `assets/`.
4. **Пусковик** `Фототрихограмма.bat` и `app/start.py`.

Сборка PyInstaller (`build.spec`) — основной путь релизного Windows ZIP.
Раздел ниже описывает только резервный способ. Она умеет обе системы:
`console=False` и иконка `.ico` подставляются автоматически.

---

### Р4. Раскладка резервного пакета

```
Phototrichogram/
├── Фототрихограмма.bat      пусковик (его и запускают)
├── ЧИТАТЬ-СНАЧАЛА.txt       инструкция для пользователя
├── app/
│   ├── start.py             подготовка окружения → запуск приложения
│   ├── phototrichogram/     исходники
│   └── assets/              шрифты DejaVu (кириллица в PDF), иконка
└── runtime/                 Windows-Python целиком
    ├── pythonw.exe          запуск без окна консоли
    ├── DLLs/                _tkinter.pyd, _sqlite3.pyd и прочие расширения
    ├── Lib/site-packages/   библиотеки из колёс
    └── Library/
        ├── bin/             tcl86t.dll, tk86t.dll, sqlite3.dll, VC++ runtime
        └── lib/             скрипты tcl8.6 и tk8.6
```

`assets/` лежит рядом с пакетом `phototrichogram` внутри `app/` не случайно:
`utils/resources.py` ищет ресурсы на уровень выше пакета.

### Р5. Поиск библиотек резервного пакета

Единственное место, где сборка может тихо развалиться.

Начиная с **Python 3.8** Windows не ищет зависимости расширений по переменной
`PATH`. Просматриваются только: каталог самого `.pyd`, системные каталоги и то,
что явно добавлено через `os.add_dll_directory()`.

В раскладке conda библиотеки `tcl86t.dll`, `tk86t.dll` и `sqlite3.dll` лежат в
`runtime/Library/bin`, то есть **не рядом** с `_tkinter.pyd` и `_sqlite3.pyd`.
Без явного `add_dll_directory` интерфейс не откроется вообще — и ошибка будет
невнятной.

Этим занимается `app/start.py`: подключает каталог библиотек и выставляет
`TCL_LIBRARY` / `TK_LIBRARY`. Наличие этой строчки **проверяется скриптом
сборки** — чтобы правку нельзя было потерять молча при рефакторинге.

Добавляя в пакет новую библиотеку с бинарными частями, проверьте, куда легли её
`.dll`. Если не рядом с её `.pyd` — каталог нужно добавить в `start.py`.

### Р6. Состав резервного пакета

### Из conda-forge (win-64)

| Компонент | Версия | Зачем |
|-----------|--------|-------|
| python | 3.12.9 | интерпретатор |
| tk | 8.6.13 | tcl/tk — на нём работает tkinter |
| sqlite / libsqlite | 3.53.4 | движок базы данных |
| ucrt | 10.0.26100 | системная C-библиотека Windows |
| vc14_runtime, vcomp14 | 14.51 | **библиотеки Visual C++** |

Строка про Visual C++ важна: это единственное, чего на чистой Windows могло не
оказаться (обычно ставится вместе с играми или офисом, но не гарантированно).
В пакете оно есть, поэтому «установите Visual C++ Redistributable» пользователю
никогда не понадобится.

### Из PyPI (колёса win_amd64)

| Пакет | Версия | Зачем |
|-------|--------|-------|
| opencv-python-headless | 4.14.0.94 | анализ изображений |
| numpy | 2.2.6 | массивы |
| matplotlib | 3.11.1 | графики динамики |
| pillow | 12.3.0 | работа с изображениями в интерфейсе |
| fpdf2 | 2.8.7 | PDF-отчёты |
| pygrabber + comtypes | 0.2 / 1.4.16 | **имена камер из DirectShow** |

`pygrabber` нужен только Windows: без него список камер выродится в
«Камера 0 / Камера 1», и перестанет работать запоминание выбранной камеры по
имени модели. В `requirements.txt` он помечен маркером
`sys_platform == "win32"` и на Linux не ставится.

Остальное — зависимости matplotlib и fpdf2, подтягиваются автоматически:
contourpy, cycler, fonttools, kiwisolver, packaging, pyparsing, python-dateutil,
six, defusedxml.

### Из самой Windows

Что берётся из системы и присутствует в любой её установке:
`kernel32.dll`, `user32.dll`, `gdi32.dll`, `advapi32.dll`, `ole32.dll`,
`oleaut32.dll`, `wsock32.dll`, `shell32.dll`, семейство `api-ms-win-*`.

OpenCV при загрузке требует из системных всего четыре — `ole32`, `oleaut32`,
`kernel32`, `wsock32` (плюс `python3.dll`, который лежит в пакете). Media
Foundation в загрузке не участвует, поэтому программа работает и на урезанных
редакциях Windows N без Media Feature Pack.

### Версии резервного runtime и диапазоны библиотек

В резервном скрипте закреплена версия Python 3.12.9 и ABI cp312.
Пакеты tk/sqlite выбирает conda, а библиотеки PyPI заданы диапазонами,
поэтому повторная загрузка через полгода не обязана дать те же версии.
Это не точный lock набора зависимостей. Релизный путь выше использует
свой закреплённый набор и сохраняет фактические версии в build-info.

Обновление версий — правка констант `PYTHON_VERSION`, `PYTHON_ABI` и
`WHEEL_SPECS` в `tools/build_windows_package.py`. Диапазоны колёс держать
согласованными с `requirements.txt`.

### Р7. Статическая проверка резервного пакета

Скрипт после сборки проверяет пакет и отказывается делать ZIP, если что-то не
так:

- на месте `pythonw.exe`, `python312.dll`, `_tkinter.pyd`, `_sqlite3.pyd`;
- на месте `tcl86t.dll`, `tk86t.dll`, `sqlite3.dll` и скрипты tcl8.6 / tk8.6;
- в `site-packages` распакованы cv2, numpy, matplotlib, PIL, fpdf, pygrabber;
- на месте исходники, шрифты и пусковик;
- `start.py` подключает каталог библиотек;
- в пакете **нет ни одного файла `.so`** — их появление означало бы, что вместо
  Windows-бинарников затесались линуксовые.

Дополнительно (руками, при существенных изменениях) полезно прогнать разбор
заголовков всех бинарников `objdump -p` и убедиться, что каждая требуемая
библиотека либо лежит в пакете, либо штатна для Windows.

**Чего проверить нельзя.** Что программа запускается и видит микроскоп.
Windows-программу на Linux не выполнить. Это остаётся за тем, у кого есть
Windows-машина с микроскопом.

### Р8. Диагностика резервного пакета

Первым делом — журнал:

```
C:\Users\<имя пользователя>\.phototrichogram\phototrichogram.log
```

Если журнала нет вовсе, значит, до кода дело не дошло — проблема в запуске
Python. Тогда запустить из командной строки, чтобы увидеть ошибку:

```
cd путь\к\Phototrichogram
runtime\python.exe app\start.py
```

`python.exe` вместо `pythonw.exe` даёт консоль, в которой видно сообщение.

Типичное:

| Симптом | Причина |
|---------|---------|
| `ImportError: DLL load failed` при импорте tkinter или sqlite3 | `start.py` не подключил `runtime/Library/bin` (см. §5) |
| Программа не стартует, журнала нет | папку запускают прямо из ZIP, не распаковав |
| Микроскоп не в списке | сменить способ подключения камеры в настройках: DirectShow ↔ Media Foundation |

---

### Р9. Данные пользователя

Хранятся **отдельно от программы**, в папке пользователя:

```
C:\Users\<имя>\.phototrichogram\
├── phototrichogram.db      вся база пациентов одним файлом
├── config.json             настройки
├── images\                 снимки
├── reports\                PDF-отчёты
└── phototrichogram.log     журнал
```

Папку с программой можно удалить или заменить новой версией — данные не
пострадают. Файл базы двоично совместим между Linux и Windows: снятое на одной
системе открывается на другой.


## Хранилище и перенос данных с 1.0.2

Windows и Linux используют один контракт: управляемые снимки лежат в `images/`
рядом с фактическим db_path, ссылки в новых записях относительные. Папка exe
не используется для пользовательских данных. Полная копия `.ptg` переносит БД
и привязанные снимки; legacy `.db` переносит только БД. Настройки и PDF отдельно.
Архив проверяется до восстановления. Установка обновления не должна заменять
папку пользовательских данных.
