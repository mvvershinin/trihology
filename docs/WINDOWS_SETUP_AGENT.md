# Windows: инструкция агенту для чистой установки готовой сборки

Назначение: развернуть Phototrichogram на Windows-машине владельца **с нуля**,
настроить USB-микроскоп и проверить полный пользовательский сценарий.
Это рабочая инструкция для Claude/Codex, а не рецепт сборки исходников.

**Договорённость владельца:** старые данные не переносить и не восстанавливать.
Использовать пустую базу. Ничего не удалять, если неожиданно обнаружены чужие
или прежние данные. Настоящий Windows/USB-микроскоп пока требует ручной приёмки:
успешные проверки GitHub Actions её не заменяют.

## 1. До начала

1. Прочитать этот файл, [руководство](USER_GUIDE.md),
   [уроки Windows](WINDOWS_LESSONS.md) и описание выбранного релиза.
   Некоторые примеры в уроках относятся к старому резервному сборщику;
   текущая поставка запускается через `phototrichogram.exe`.
2. Зафиксировать Windows edition/build, архитектуру x64, модель микроскопа,
   выбранный тег релиза и пользователя Windows. Работать в его обычном сеансе,
   не под администратором и не из служебного аккаунта агента.
3. Нужна Windows 10/11 x64. Python, SQLite, pip и среда разработки для ZIP
   не нужны. Не устанавливать их ради исправления запуска готовой поставки.
4. Проверить, что другая копия программы не запущена. Не завершать процесс
   с несохранёнными данными без участия пользователя.
5. Не публиковать ФИО, снимки, базу, конфигурацию и полный журнал в GitHub.
   Для проверки использовать вымышленного пациента и тестовый материал.

## 2. Скачать и распаковать

1. Открыть [GitHub Releases](https://github.com/mvvershinin/trihology/releases/latest).
   Использовать опубликованный выпуск **не ниже v1.0.2**: в нём исправлено
   хранение снимков. Записать фактически выбранный тег, не предполагать,
   что последняя версия по-прежнему v1.0.2.
2. Скачать из одного и того же релиза `Phototrichogram-win64.zip`,
   `SHA256SUMS` и `build-info.json`. Архивы «Source code» не подходят.
3. В PowerShell из папки загрузки выполнить:

   ```powershell
   Get-FileHash .\Phototrichogram-win64.zip -Algorithm SHA256
   Get-Content .\SHA256SUMS
   ```

   Сравнить хеш со строкой именно `Phototrichogram-win64.zip`. При несовпадении
   не запускать файл: скачать повторно и разобраться с источником.
4. Распаковать **весь** ZIP, например в
   `%LOCALAPPDATA%\Programs\Phototrichogram\<версия>\`.
   Не смешивать разные версии и не вытаскивать один EXE без остальных файлов.
   Найти `phototrichogram.exe` внутри распакованного каталога.
5. Если Windows показывает SmartScreen, проверить источник и хеш, затем
   использовать доступный штатный вариант запуска доверенного файла.
   Не отключать Defender/SmartScreen, не добавлять массовые исключения и
   не обходить корпоративные запреты. Если запуск заблокирован политикой —
   зафиксировать сообщение и передать вопрос владельцу/администратору.

## 3. Убедиться, что профиль чистый

По умолчанию данные лежат **вне программы**:

```text
%USERPROFILE%\.phototrichogram\
  phototrichogram.db
  config.json
  images\                 исходники и разметка возле фактической БД
  reports\                папка PDF по умолчанию
  phototrichogram.log
```

Перед первым запуском проверить:

```powershell
Get-Item Env:PHOTOTRICHOGRAM_DATA_DIR -ErrorAction SilentlyContinue
Test-Path "$env:USERPROFILE\.phototrichogram"
```

- Если переменная не задана и папки нет — запуск создаст новый профиль.
- Если папка есть — **не удалять её** и не считать запуск чистым. Проверить
  с владельцем назначение папки. Для этой задачи выбрать отдельную новую
  папку, не импортируя ничего из прежней.
- Если переменная задана, сначала выяснить её назначение: она меняет профиль.

Для нового отдельного профиля в текущем PowerShell, например:

```powershell
$profilePath = Join-Path $env:USERPROFILE '.phototrichogram-fresh'
if (Test-Path $profilePath) { throw 'Profile already exists; choose a new folder.' }
$env:PHOTOTRICHOGRAM_DATA_DIR = $profilePath
# Выполнять из каталога, содержащего EXE:
.\phototrichogram.exe
```

Эта переменная действует только для процессов, запущенных из данного терминала.
Обычный двойной щелчок её не наследует. Если выбран отдельный профиль для
постоянной работы, сделать рядом с EXE `Start-Phototrichogram.cmd` с **точным
выбранным именем папки**, например:

```bat
@echo off
set "PHOTOTRICHOGRAM_DATA_DIR=%USERPROFILE%\.phototrichogram-fresh"
start "" /D "%~dp0" "%~dp0phototrichogram.exe"
```

В этом случае ярлык должен указывать на CMD. Проверить запуск двойным щелчком
именно по этому ярлыку. Для обычного профиля ярлык указывает прямо на EXE;
не менять системные переменные окружения ради запуска.

## 4. Первый запуск обычным способом

1. Запустить двойным щелчком EXE или подготовленный профильный ярлык.
2. Убедиться, что окно открылось, вкладки доступны, старых пациентов нет.
   Если записи появились — остановить настройку и проверить фактический профиль.
3. Через «Справка → О программе», если пункт доступен, и `build-info.json`
   сверить версию. Зафиксировать фактический путь данных и путь к EXE.
4. Проверить создание БД, настроек и журнала в выбранном профиле. Не копировать
   их в каталог поставки. Не задавать `images_dir` из старой сборки: связанные
   снимки управляются хранилищем `images` рядом с фактической БД.
5. Закрыть и снова открыть тем же ярлыком: должен использоваться тот же профиль.

## 5. Подключить микроскоп

1. Подключить микроскоп к USB, снять защитную крышку, включить освещение.
   При сбоях проверить другой порт/кабель, по возможности без USB-хаба.
2. Проверить устройство в диспетчере устройств. Если драйвер отсутствует,
   выяснить точную модель; не скачивать драйверы с произвольных сайтов.
3. При необходимости проверить изображение штатной «Камерой» Windows,
   затем **закрыть её**, а также Teams/Zoom и другие программы, занимающие камеру.
4. В параметрах конфиденциальности Windows проверить разрешение доступа
   к камере для приложений и настольных приложений. Точные переключатели
   зависят от версии Windows и политики компьютера; см.
   [инструкцию Microsoft](https://support.microsoft.com/en-us/windows/privacy/manage-app-permissions-for-a-camera-in-windows).
   Менять только необходимые разрешения с ведома владельца.
5. В Phototrichogram открыть «Захват», обновить список устройств, выбрать
   **микроскоп**, а не встроенную веб-камеру, и нажать «Подключить».
   Проверить живой кадр, фокус, освещение и фактическое разрешение.
6. По умолчанию `camera.backend = "auto"` перебирает DirectShow и MSMF.
   При отказе сохранить текст ошибки/журнал. Для точечной диагностики можно
   закрыть программу, сохранить копию `config.json` и поменять только
   `camera.backend` на `"dshow"` или `"msmf"`, затем повторить запуск.
   Не перезаписывать конфигурацию целиком и не редактировать её при работающем
   приложении. Если backend не помог — вернуть исходное значение.

## 6. Калибровка и первое обследование

1. Использовать микрометрическую шкалу и то увеличение/разрешение, с которыми
   будут выполняться обследования. На вкладке «Калибровка» загрузить её снимок,
   выполнить автокалибровку или ввести **измеренный** масштаб вручную и нажать
   «Сохранить калибровку».
2. Не принимать заводское значение 5.9 мкм/пиксель за калибровку этой машины.
   При смене увеличения, разрешения или оптики калибровку проверить заново.
   Без шкалы можно проверить интерфейс, но точность измерений не подтверждена.
3. На вкладке «Пациенты» создать вымышленного тестового пациента и выбрать
   его двойным щелчком; проверить активного пациента в строке состояния.
4. На «Захвате» получить снимок зоны или загрузить тестовое изображение,
   нажать «Анализировать загруженные», дождаться результатов и сохранения.
   Без выбранного пациента сохранение обследования не считать проверенным.
5. В «Истории» выбрать конкретную строку, нажать «Снимки» либо открыть её
   двойным щелчком/Enter. Проверить исходник и доступную разметку.
6. Проверить появление файлов в `images/` рядом с БД. Для проверки внешнего
   импорта взять копию тестового файла из отдельной временной папки; после
   сохранения закрыть программу, переименовать только эту временную папку,
   снова открыть приложение и проверить снимок в истории. Оригинал владельца
   не перемещать и не удалять.
7. Создать PDF, открыть его обычной программой Windows и проверить текст,
   цифры и изображение. Закрыть/снова открыть Phototrichogram и убедиться,
   что обследование и снимок доступны.

## 7. Проверить резервную копию

1. «Файл → Резервная копия базы...» → полный архив `.ptg` во внешнюю папку.
   Он включает БД и связанные снимки. `config.json` и экспортированные PDF
   сохраняются отдельно. `.db`/`.sqlite` — только база, без изображений.
2. Для проверки восстановления закрыть приложение и запустить **отдельный
   новый тестовый профиль**, как в разделе 3. Не восстанавливать поверх
   рабочего профиля ради теста.
3. «Файл → Восстановить из копии...» → созданный `.ptg`. Убедиться, что
   восстановились тестовое обследование и снимки. Закрыть тестовую копию.
4. Вернуться к рабочему ярлыку/профилю. Не оставлять два одновременно
   запущенных экземпляра, обращающихся к одной БД.

## 8. Если не запускается / критерии сдачи

При отказе проверить полную распаковку и журнал в выбранном профиле. Если
журнала нет, сохранить точное сообщение Windows: сбой возможен до старта Python.
Не лечить его установкой случайных DLL, Python или запуском от администратора.
Не отключать защиту. Зафиксировать версию, путь запуска и последовательность
действий; отделять проблему поставки от прав камеры и ошибки анализа.

На чистой машине отдельно отметить наличие Python и внешнего VC++ runtime.
Не удалять их с рабочего компьютера ради эксперимента: проверку без них делать
на отдельной чистой VM/машине. Обычный запуск на ПК разработчика её не заменяет.

По завершении обновить общий [BACKLOG](todo/BACKLOG.md) и текущий план,
записав результаты без персональных данных:

- тег/ревизия, SHA-256, Windows build, модель микроскопа;
- обычный двойной щелчок, пустая БД и повторный запуск — результат;
- подключение, кадр, калибровка — что выполнено, что не проверено;
- сохранение → история → исходник/разметка → PDF — результат;
- полный `.ptg` → отдельный профиль → восстановление снимков — результат;
- путь к ярлыку, программе, данным и копии; найденные ошибки;
- отдельно: проверена ли машина без Python/внешнего VC++ runtime.

Не писать «Windows принят», если проверен только запуск окна или не подключался
реальный микроскоп. Если агент не имеет управления Windows-интерфейсом,
передать владельцу эти шаги и честно отметить непроверенное.
