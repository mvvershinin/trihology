## Что уже готово (контекст)

Приложение функционально завершено как измерительный инструмент трихоскопии:
анализ снимков (сегментация → измерение → классификация), калибровка,
персональные нормы по демографии, серия снимков с усреднением, подсчёт «от
корней» (опция), история с графиками и просмотром снимков, PDF-отчёты, бэкап
базы, сборка в один дистрибутив. 472 теста, mypy strict, слои под контрактом.

## Оставшиеся задачи

### 1. Подсчёт «от корней» — дефолт  ✅ СДЕЛАНО 2026-08-08

Решение пользователя: считаем только растущие волосы. `count_mode="rooted"` —
дефолт `AnalysisConfig`, прежний подсчёт остался в настройках («Все волосы»).

Режим в БД не пишется, поэтому старые измерения (в режиме «все») и новые лежат
в истории рядом и на графике дают обрыв плотности. Решение пользователя: старые
данные во внимание не берём, колонку `count_mode` не заводим. Вопрос закрыт.

### 2. Верхняя граница нормы  ✅ СДЕЛАНО 2026-08-08

Верхняя граница подавалась как жёсткий потолок, хотя `NormRange.status` выше
`high` считает значение нормой (густые волосы — не патология). Задача была
записана как «только текст», но по факту врала и разметка графика.

- График плотности (`history_tab.py`): полоса нормы открыта вверх, как у T/V;
  `high` — серый пунктир «типично до N».
- Отчёт (`pdf_report.py`): пороги как «Плотность ≥N/см²», «Толщина ≥N мкм»
  (было `low–high`, читалось потолком); типичные верхние значения — отдельной
  серой строкой «не потолок нормы». Формирование вынесено в чистую
  `_format_norm_ranges()` и покрыто тестами.
- То же исправлено для толщины — та же ошибка в той же строке отчёта.
- METHODOLOGY §2.2 — как читать верхнюю границу.

### 3. v1.3 — Дерматоскопические признаки  ⏱ 3–5 дней · новая большая фича

**Суть**: детекция на снимках скальпа паттернов, которые оценивает трихолог:
- Перифолликулярный фиброз — белые ореолы вокруг фолликулов
- Себорея — жёлтые чешуйки/корки (сегментация в HSV)
- Yellow dots — пустые фолликулы (жёлтые круглые объекты)
- Black dots — обломанные волосы (мелкие тёмные точки)

Результат: наличие/отсутствие каждого признака + процент площади. БЕЗ диагнозов
— только наличие признака, как и остальные метрики.

**Как**: новый `core/dermatoscopy.py` — детекторы по цветовым пространствам и
морфологии, все пороги в `AnalysisConfig`. Новая вкладка/секция в GUI. Признаки
в БД (миграция) и в PDF-отчёт. Валидация на реальных снимках с подтверждёнными
признаками (нужны такие снимки от пользователя).

**Слои**: core (детекторы), data (хранение), gui (показ), reports (в PDF).
Фазы: core+tests → data-миграция → gui → reports. Ревью каждой.

### 4. v2.0 — Крупные направления  ⏱ недели · по мере необходимости

- **Windows-поддержка**: камера через DirectShow (`cv2.CAP_DSHOW`), сборка
  `.exe`, проверка кириллицы шрифтов. Основной код кроссплатформенный.
- **Watershed** для слипшихся волос: разделение объединённых контуров (глубже,
  чем текущий фильтр пучков по толщине).
- **ML-классификация**: обучаемая модель Terminal/Vellus вместо порога по
  толщине — требует размеченного датасета.
- **CI/CD**: GitHub Actions — прогон тестов/линтеров на push, автосборка
  релизов (AppImage/exe).

## Принципы (не менять)

- Приложение — измерительный инструмент, НЕ диагност: никаких диагнозов, названий
  болезней, рекомендаций. Только метрики + справочные нормы с оговоркой.
- Все клинические числа — с оговоркой «справочно, не диагноз».
- Новые пороги/параметры — в конфиг, не хардкод. Новые режимы — переключаемые,
  дефолт сохраняет прежнее поведение.
- После кода — architecture-validator + code-critic (медицинскую математику
  проверять адверсарно). Слои под контрактом import-linter.
- Медицинские данные — честно: при сомнении отказ/предупреждение, а не
  правдоподобный мусор.
