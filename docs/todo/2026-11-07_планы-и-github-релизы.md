## Согласованное устройство релизов

Перенести из trade последовательность **тег → проверки → две сборки → релиз**,
единую версию и единый локальный/CI рецепт. Nuitka, uv и библиотеки Qt не
переносить: у нас tkinter и готовый PyInstaller spec.

| Платформа | Основной путь сборки | Скачиваемый файл |
|---|---|---|
| Linux x86_64 | PyInstaller onedir → AppImage, база Ubuntu 22.04 | `Phototrichogram-linux-x86_64.AppImage` |
| Windows x86_64 | Нативный Windows runner → существующий build.spec → ZIP всего onedir | `Phototrichogram-win64.zip` |
| Обе | SHA-256 файлов и сведения о версии/ревизии/зависимостях | `SHA256SUMS`, `build-info.json` |

Имена файлов и внутренняя структура стабильны между релизами; версия живёт в
теге, программе и сведениях о сборке. В Windows ZIP — `phototrichogram.exe`,
зависимости, ресурсы и русская инструкция. Python устанавливать пользователю
не требуется. Данные остаются в `~/.phototrichogram`, вне поставки.
Старый Linux→Windows сборщик оставить резервным документированным способом;
он не является вторым обязательным Windows-артефактом каждого релиза.

Триггеры: обычный CI — push/PR основной ветки; выпуск — только push тега
`vX.Y.Z`. Ручной `workflow_dispatch` — пробная сборка с артефактами Actions,
без автоматической публикации. Проверять формат тега до тяжёлых сборок.
Первый номер релиза — `v1.0.0`, если проверка remote не обнаружит конфликт.
